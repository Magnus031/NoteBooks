    内存申请

    因为笔记中没有专门的放操作系统的内容，基本都在 Linux 中进行讲述

    内存申请

    在 Linux 中的内存申请的系统调用主要有以下2种:

    1. brk 和 sbrk：这两个系统调用用于调整进程的数据段的大小。brk 设置数据段的结束地址，而 sbrk 则是相对于当前数据段结束地址增加或减少指定的字节数。
    2. mmap：这个系统调用用于将文件或设备映射到内存中。它可以用于分配大块内存，并且支持共享内存和匿名内存映射。

    brk 和 sbrk

    sbrk 缩写是 increment break, 这里的break 指的是程序数据段 (data segment) 的结束地址, 通过增加或减少这个地址来动态地改变程序的内存大小

    // xv6 中的 sbrk 实现
uint64
sys_sbrk(void)
{
  uint64 addr;
  int n;

  argint(0, &n);
  addr = myproc()->sz;
  if(growproc(n) < 0)
    return -1;
  return addr;
}

// Grow or shrink user memory by n bytes.
// Return 0 on success, -1 on failure.
int
growproc(int n)
{
  uint64 sz;
  struct proc *p = myproc();

  sz = p->sz;
  if(n > 0){
    if((sz = uvmalloc(p->pagetable, sz, sz + n, PTE_W)) == 0) {
      return -1;
    }
  } else if(n < 0){
    sz = uvmdealloc(p->pagetable, sz, sz + n);
  }
  p->sz = sz;
  return 0;
}

// Allocate PTEs and physical memory to grow process from oldsz to
// newsz, which need not be page aligned.  Returns new size or 0 on error.
uint64
uvmalloc(pagetable_t pagetable, uint64 oldsz, uint64 newsz, int xperm)
{
  char *mem;
  uint64 a;

  if(newsz < oldsz)
    return oldsz;

  oldsz = PGROUNDUP(oldsz);
  for(a = oldsz; a < newsz; a += PGSIZE){
    mem = kalloc();
    if(mem == 0){
      uvmdealloc(pagetable, a, oldsz);
      return 0;
    }
    memset(mem, 0, PGSIZE);
    if(mappages(pagetable, a, PGSIZE, (uint64)mem, PTE_R|PTE_U|xperm) != 0){
      kfree(mem);
      uvmdealloc(pagetable, a, oldsz);
      return 0;
    }
  }
  return newsz;
}

    mmap

    mmap：现代操作系统动态内存分配的利器

    mmap 是一个系统调用，全称是 memory map，也就是内存映射。它在现代操作系统（如 Linux、macOS）中扮演着至关重要的角色，是实现高效动态内存分配的核心机制之一，也是虚拟内存管理的基础。

    与传统的 sbrk 扩展堆的方式不同，mmap 的工作方式更灵活，也更强大。它可以将一个文件或一段匿名内存映射到进程的虚拟地址空间中。

    mmap 的基本原理是：它创建一个从进程的虚拟地址空间到某个物理存储介质（如磁盘文件或物理内存）的映射。

    mmap 的两种主要用途

    1. 文件映射（File-backed Mapping）：

      • 作用： 将一个文件映射到进程的虚拟地址空间。
      • 工作方式： 进程可以通过直接读写这段虚拟地址，来间接读写文件内容，而无需使用传统的 read() 或 write() 系统调用。
      • 优点：
        • 高效 I/O： mmap 允许操作系统使用页缓存（Page Cache）来管理文件的读写。当进程访问映射区域时，如果数据不在内存中，会触发缺页中断，操作系统会自动从磁盘加载相应的数据页到物理内存。
        • 减少系统调用： 程序可以直接像访问内存一样访问文件，避免了频繁的系统调用开销。
      • 示例： 在处理大文件时，mmap 可以让你像处理一个大数组一样处理文件内容，而不用担心一次性将整个文件加载到内存中。

    2. 匿名映射（Anonymous Mapping）：

      • 作用： 创建一段没有关联文件的、独立的内存区域。
      • 工作方式： 操作系统在进程的虚拟地址空间中划定一块区域，但并不会立即为其分配物理内存。只有当进程首次访问这段内存时，才会触发缺页中断，操作系统才会真正地分配物理页。
      • 优点：
        • 懒惰分配（Lazy Allocation）： 这是现代内存管理的核心思想。它实现了按需分配，只有真正使用时才占用物理内存，从而提高了物理内存的利用率。
        • 内存对齐： mmap 分配的内存是以页为单位对齐的，这与操作系统的内存管理机制完美契合。
        • 独立性： 匿名映射分配的内存区域可以独立于传统的堆，这让内存管理更加灵活，避免了堆碎片化的问题。

    operator new 在现代 C++ 中就经常使用匿名 mmap 来请求大块内存。

    mmap 如何实现动态内存分配？

    当 operator new 需要分配一大块内存（例如超过 4KB，这个阈值由编译器和操作系统决定）时，它会调用 mmap 并使用 MAP_ANON（匿名映射）和 PROT_READ|PROT_WRITE（读写权限）等标志。

    整个过程是这样的：

    1. new 请求： 你的程序调用 new T;。
    2. operator new 调用 mmap： 标准库的 operator new 函数向操作系统发出一个 mmap 系统调用，请求一段指定大小的匿名内存。
    3. OS 分配虚拟地址： 操作系统在进程的虚拟地址空间中找到一块空闲区域，并将其标记为已分配。此时，没有物理内存被分配。mmap 调用成功返回一个指向这段虚拟地址的指针。
    4. new 返回指针： new 表达式得到这个虚拟地址并返回给你。
    5. 首次访问触发 Page Fault： 当你的程序第一次解引用这个指针并尝试读写时，CPU 发现该虚拟地址没有对应的物理内存映射，于是引发缺页中断。
    6. OS 分配物理内存： 操作系统内核捕获中断，从物理内存中分配一个或多个页，并更新进程的页表，建立虚拟地址到物理地址的映射。
    7. 指令重试： 控制权返回给你的程序，之前失败的读写指令成功执行。

    通过这种方式，mmap 完美地支持了懒惰分配，将物理内存的分配推迟到了真正需要使用时。这正是现代操作系统高效利用内存的关键。

    sbrk 和 mmap 的对比

    特性 sbrk mmap
    内存位置 扩展数据段的末尾（堆） 独立的内存区域，不一定在堆上
    分配方式 增量式分配 按需一次性分配大块内存
    物理分配 通常是即时的，但现代OS也有优化 惰性分配（Lazy Allocation）
    内存回收 只能收缩堆尾，不灵活 可以通过 munmap 释放任意一段内存
    主要用途 传统堆管理 匿名内存分配、文件映射、共享内存

    总的来说，sbrk 是一种老式、简单的堆扩展方式，而 mmap 则是一种更先进、更灵活、更强大的内存管理机制。这也是为什么现代操作系统和编译器更倾向于使用 mmap 来实现动态内存分配。
